文章把 Super-agent 定义成一个连续的实体：上下文跨会话保留，多件复杂工作同时推进，彼此不搅在一起。它列出四个特征。

| 特征 | 文章里的意思 | 你可以想到的前端类比 |
| --- | --- | --- |
| Continuous | 人在 IM 和 GitHub 里面对的是同一个智能体 | 同一个账号在不同页面看到同一份数据 |
| Productive | 上一件还没做完，下一条指令也能接 | 界面不因为一个慢请求把整页锁死 |
| Proactive | 环境事件来了就判断要不要做，没事就安静 | 只有该响的通知才会响 |
| Persistent | 一直在线，设备睡了也能恢复 | 任务队列不绑在某一台笔记本的开机状态上 |

文章写明，没有任何一个 ReAct 循环能同时提供这四样，所以它们来自循环外面的系统。五个模块是：

1. 两层结构，负责连续对话和并行干活。
2. 事件驱动的触发，负责主动。
3. 全双工、多渠道的交互，负责每天说话的方式。
4. 计算、状态、执行环境分开。
5. 外部的 Watchdog，负责长跑时的异常。

原型用自己的领域词把能落地的部分写成了对象。来源产出触发。触发属于一条或几条线程。评估决定要不要开新工作。接受之后生成带授权的工单。派工把工单交给执行器。订阅让后续触发直接到达已经在做的工单。面板上的「待人工决定」是工单上的一个问题。

哲学文档把原则收成一句：尽可能少占用人类的注意力，尽可能多给出价值。智能体只在被要求时行动，或在团队写成的规则允许时行动；只在人必须行动或用得上结果时开口。

## 练习

1. 把四个特征各写成一句你自己的话，不要复述表格。
2. 在 001 的术语表里找到 Trigger、Ticket、Attention 的中文。
3. 标出哪两个模块你已经能在原型文档里找到同名机制，哪两个要等后面几课对照。
