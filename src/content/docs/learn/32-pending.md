原型的 [005 Panel](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/005-panel.md) 把打开面板后的三个问题排了序：现在有没有事要我处理，系统是否健康，一件工作从触发到评估再到工单的历史是什么。标签页按这个顺序：概览、来源、触发、评估、执行、设置。概览把需要行动的工单放在最前，每一块都能点进详情。健康的数字不额外占地方。

工单阶段从表上往下，第一行命中的为准。和人有关的包括：输入没送到、有待回答的问题、最新报告是 ready 因而等验收、被阻塞或失败。实验室的待决定栏收了其中三种：要一个决定、等验收、做失败了。角标是这三种的件数。没有件数时，栏里只有一句「现在没有要你处理的事」。

界面上的规则：

1. 空状态用虚线框说明为什么是空的，不留一块没有内容的色条。
2. 问题和验收、失败各自有自己的按钮。自动播放停在这些按钮上，不会替你点。
3. 还有待决定事项、而且时间线已经走到最新一步时，「下一步」是禁用的。
4. 三栏的标题在同一行。窄屏改成上下堆叠。
5. 每一步下面有一句概念说明，链到对应的课。

组件是 `src/components/Lab.tsx`。它不保存密钥，也不发请求。每一次点击都调用 `apply`。

原型还有检索：按文本、id、飞书消息 id 或 GitHub 评论链接找触发。本课的三件事太少，没有做搜索。设置、来源开关和部署问题也没有做。那些属于 006 的运维界面，不是这台教学状态机的范围。

## 练习

1. 在 390px 宽的窗口里走完「GitHub 点名 → 同一线程的 CI → 改成 480px → 验收通过」，确认三栏变成一列。
2. 用键盘完成「改成 480px」。角标应从 1 变成 0 或换成验收。
3. 送入「@agent 这个崩溃无法复现」，确认失败项有重试和停止。
