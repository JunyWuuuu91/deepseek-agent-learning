原型的 [005 Panel](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/005-panel.md) 把打开面板后的三个问题排了序：现在有没有事要我处理，系统是否健康，一件工作从触发到评估再到工单的历史是什么。标签页按这个顺序：概览、来源、触发、评估、执行、设置。概览把需要行动的工单放在最前，每一块都能点进详情。健康的数字不额外占地方。

工单阶段从表上往下，第一行命中的为准。和人有关的包括：输入没送到、有待回答的问题、最新报告是 ready 因而等验收、被阻塞或失败。本站的面板只实现了其中「有一个具体问题」和「等验收」。

界面上的规则：

1. 没有问题时，右栏写明面板为什么是空的。
2. 有问题时，主按钮是同意的那一种改法，次按钮是先不做。两个按钮都会把状态机推进到终态或验收态。
3. 问题还在时，「下一步」禁用。禁用要有 `disabled`，不只是把颜色变淡。
4. 日志用角色区分准入、路由、工人和你，不靠颜色单独传达。
5. 窄屏上三栏改成上下堆叠。事件、过程和决定仍然都在。

组件是 `src/components/Lab.tsx`。它不保存密钥，也不发请求。你在[实验室](/learn/lab/)里点的每一次，都是 `advance` 或 `resolveAttention`。

原型还有检索：按文本、id、飞书消息 id 或 GitHub 评论链接找触发。本课的三件事太少，没有做搜索。设置、来源开关和部署问题也没有做。那些属于 006 的运维界面，不是这台教学状态机的范围。

## 练习

1. 在 390px 宽的窗口里走完一遍，确认三栏变成一列，按钮不被挤出屏幕。
2. 用键盘只靠 Tab 和 Enter 完成「改成 480px」。
3. 读 005 的七条原则，挑一条你的面板已经遵守的，和一条还没做的。
