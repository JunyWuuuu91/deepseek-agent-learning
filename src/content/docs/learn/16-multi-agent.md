---

一个会话就像一个浏览器标签：里面的历史别的标签看不见。你开五个聊天，就要自己记住哪个标签里有那份报错。DeepSeek 的架构文章把这说成经验：一个人通常同时跟得住 3 到 5 个活跃会话。单任务的上限来自模型，多任务的上限来自人的注意力。这句话是文章里的经验，不是本课重复做的实验。

两种「多个智能体」容易混在一起。

Agent Team 通常把一个大任务拆成紧耦合的步骤。领队要懂任务细节，不断协调。文章认为这会把推理负担留在主会话上。

Router–Worker 把「跟人说话、记住全局」和「干活」分成两层。路由层不执行任务，工人各自带着隔离的上下文做一件事，不直接回复用户。文章写明：如果用提示词禁止主会话自己干活，只许它对外交流并把独立任务派出去，Agent Team 也可以变成这种两层结构。公开原型选择了结构上的限制：主会话的预设工具更少，工人的预设才带齐文件和子代理。

工人之间通常不需要点对点说话。冲突发生在同一份工作环境，比如同一个拉取请求。订阅了同一条线程的工人会看到同一条事件。这是后面触发那一课的内容。

子代理是工人内部的事。原型的 `cordis.patch.yml` 让工人可以拉起 Harness 的 `standard` 预设子代理，路由预设里则没有子代理工具。对路由层来说，工人仍是一个执行单位。

## 练习

1. 拿你现在的编辑器：如果五个聊天同时改同一个文件，你会怎么合并？写三句。
2. 读文章第二节，用自己的话写出「连续性」和「吞吐」这一对矛盾。
3. 指出原型里哪个预设名字对应路由，哪个对应工人。答案在 [25 课](/learn/25-router-worker/)。
