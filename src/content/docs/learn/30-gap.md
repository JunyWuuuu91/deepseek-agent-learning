文章第 7 节声明实验使用合成负载和简化环境，结果只供参考。编码工作被一个只会消耗时间的工具代替，所以它量的是调度，不是写代码的能力。每种设计跑了 5 次。

X 文章里的表是：

| 设计 | 任务完成时间 p50 / p95（分钟） | 每次运行的缓存读取 token |
| --- | --- | --- |
| Super-agent | 12.4 / 15.7 | 23.2M |
| 去掉 Pass-through | 12.6 / 15.5 | 31.8M |
| 单会话 + 子代理，中性提示 | 20.4 / 29.5 | 6.1M |
| 单会话 + 子代理，倾向委派的提示 | 13.8 / 29.0 | 10.8M |

正文还写到：去掉 pass-through 后，路由的决定大约多 30%，缓存读取从 23.2M 增到 31.8M，大约多 37%。中性提示的 5 次运行里模型没有调用子代理。倾向委派的提示有 4 次委派，剩下 1 次模型认为工作「很小」就自己做了。

路由批处理的压测：需要决定的触发从大约每分钟 1 条加到大约 40 条，平均批量从 1.0 到 2.8，单次请求从 2.5 秒到 3.9 秒，摊到每次决定上的推理时间从 6.4 秒降到 1.6 秒。这些数字出现在文章里。本课没有在原型的 000 到 008 里找到同一组实验复现。

下面只对照本课读过的公开文件。

| 文章中的设计 | 在公开原型文档或 cordis.patch.yml 里能对上的 |
| --- | --- |
| 两层路由 / 工人 | 主会话与每张工单一个执行器会话，两份预设 |
| 快慢过滤 | 准入代码 + 模型研判；`off` / `observe` / `auto` |
| 订阅直达 | 扇出；人的后续消息不再评估 |
| Inline / Spill / Chain of Recall | 截断卡片、读取指针、按 id 分页。文章里的这三个名字没有出现在 000–008 |
| 投机执行 | 未找到「先做再丢弃」的模块。`observe` 是记录而不执行 |
| `start()` / `stop()` | 未在这些文件里找到同名工具。找到的是 5 秒转入后台 |
| 多渠道话术 | 100 词上限，GitHub 写结构化说明 |
| 计算、状态、环境分离和 BYOM 守护进程 | 未按文章实现。循环、SQLite 和工作目录在同一台机器的一个进程里 |
| 判断目标是否偏离的 Watchdog 会话 | 未找到。找到的是另一个配置里的每小时进程检查 |
| 第 8 节的扩展、无会话的产品形态、跨实例 A2A、凭据完全不进入模型 | 文章列为开放问题 |

第 8.3 节在补读的译文里说：一个实例内部假定信息汇入一份全局上下文；组织变大时，要共享上下文的范围放在一个实例里，要隔离的范围分成多个实例。实例之间的协调是一般意义上的智能体对智能体通信，不是某一个具体协议。安全可靠地跨过不同权限边界，文章认为仍是开放的。

第 8.4 节说：事件驱动扩大了不可信输入；云端循环如果被攻破或被提示注入，就可能影响到每台连上的设备；还需要一种使用凭据时模型碰不到凭据本身的机制。原型已经写明的相关事实是：执行器以操作者的系统用户运行命令且默认不逐条批准，包装器不是安全边界，执行变量里不放凭据。

## 练习

1. 不看表，说出中性提示那 5 次运行里子代理被调用了几次。
2. 从表格里挑两行，写成「文章描述了什么」和「公开仓库写了什么」。
3. 读 007 末尾的开放问题，看信任边界和部署隔离是不是仍被列为未完成。
